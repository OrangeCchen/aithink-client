# 文档类型与场景单元拆分

先定类型，再拆单元。一个单元 = 一次可独立回答「公务员会不会遇到」的工作主张。

## 现场演示脚本

**识别信号**：口播、现场输入、兜底结果、授信文件夹、一天叙事。

**单元粒度**：通常按演示章节拆（安全授权、要情速递、会议纪要、调研报告、表格汇总等各 1 单元）。

**主判**：这一步是不是该岗位当天/当周会干的活？口播有没有把辅助能力说成替代审批？

**参照侧重**：投促/综合岗公开职能；会议与办文规范；安全授权话术是否符合机关习惯。

## 汇报 / 售前逐字稿

**识别信号**：各位领导、本页、竞品、回本、部署周期、六大场景。

**单元粒度**：每个能力主张或场景段 1 单元（如「公文辅助」「流程督办」「政策检索」）。

**主判**：机关听众是否认这是自己的工作？有没有不可验证断言冒充真实遭遇？

**参照侧重**：办文办会办事公开表述；对「秒级/替代审批/跨系统自动办结」要严查。

## 建设内容 / 功能清单

**识别信号**：表格、三级目录、套×1、功能描述列、建设板块。

**单元粒度**：一行，或一个有完整业务含义的三级目录能力；纯平台底座（任务编排引擎等）可合并为「平台能力」单元，并注明「不是机关业务遭遇本身」。

**主判**：描述的是真实机关任务，还是企业场景挪词 / 同义拆条？

**参照侧重**：政企受众是否错位；接收对象是「报送上级/呈领导」还是「企业投标/融资」。

## 拆分回显示例

```text
拟评审单元：
1. 政务要情定时速递
2. 招商调度会纪要与待办
3. 区县调研材料分析报告
4. 多区县上报表汇总
```

确认或微调后再逐条六问判定。
